# ADR-0002：离线优先记录与操作批量同步

> 状态：Accepted for Phase 1
>
> 决策日期：2026-08-12
>
> 跨项目统一编号：ADR-0023（见 [ADR_INDEX.md](../../../docs/decisions/ADR_INDEX.md)）

## 背景

Moment One 的核心价值是快速留下生活记录。网络不可用时要求用户等待单条远端请求，会让“先记录”这一主流程失败。现有 REST API 已具备认证、所有权、幂等和 Revision 约束，但没有客户端离线操作队列的统一同步入口。

## 决策

1. 在线客户端的主动创建、修改实时调用领域 REST API；本地 IndexedDB 是网络不可用或网络级失败时的兜底队列，不是正常在线保存的前置步骤。
2. Server 新增业务同步操作批处理入口，而不是恢复历史的账户同步代理接口。
3. 批次中的操作独立处理并逐条返回结果；允许部分成功，禁止以全量数据覆盖云端。
4. 同步处理器复用领域服务或同一用例实现，必须保持认证、所有权、类型校验、幂等、Revision、审计和通知派生的一致性。
5. Moment 创建接受客户端生成 UUID；同一用户内 ID 不可被不同请求占用。
6. 更新继续使用 `expectedRevision`；冲突不得静默覆盖。
7. 删除、媒体上传、手动提醒、账号安全、设备/MCP 授权不进入第一期离线队列。提醒在补齐独立的客户端 ID、幂等与状态机契约后另行接入。
8. 客户端以刷新或明确“同步”作为离线队列的主要提交时机；网络恢复只提示可同步，不依赖浏览器 Background Sync。在线保存本身不等待手动同步。
9. 客户端时间戳只用于排序说明和审计，不使用 Last-Write-Wins。并发仲裁以
   `expectedRevision`、操作幂等凭证、服务端 Revision 与 Tombstone 为准；删除后修改绝不自动复活资源。

## 影响

- Server 是业务事实源，客户端缓存和操作队列不是权威副本；
- 创建、修改在线时立即成为服务端事实；离线或网络级失败时形成可恢复的本地状态；
- 同步成功可安全重试，失败与冲突可明确呈现；
- 删除、修改与并发操作都有 Revision、版本快照和审计事件作为可追溯证据；
- 退出、注销、换账号必须清除对应本地数据分区；
- 后续 Glasses 可以复用相同同步契约。

## 不在本决策中的事项

- 媒体断点续传与离线上传会话；
- 自动冲突合并算法；
- 后台自动同步保证；
- 对所有设置、安全和授权操作的离线化。
